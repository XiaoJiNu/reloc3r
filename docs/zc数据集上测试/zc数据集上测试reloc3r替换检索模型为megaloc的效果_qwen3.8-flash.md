# Reloc3r 检索段替换为 MegaLoc 的效果（zc 数据集，qwen3.8-flash）

执行环境：/data/software/conda/anaconda3/envs/mv2d ｜ GPU：RTX 5090 Laptop ｜ 脚本：`eval_zc_megaloc_reloc3r.py`（repo 根）｜ 产物：`data/zc_megaloc_reloc3r/`
对照数据：Reloc3r-NetVLAD 基线见《zc数据集上测试reloc3r效果_qwen3.8-flash-202609281505.md》与《zc数据集0923两包测试reloc3r效果及资源统计_qwen3.8-flash-202609281636.md》；MegaLoc 纯检索评测见《/data/code/reLocation-all/MegaLoc/doc/自研数据复现/MegaLoc在zc自研数据上的重定位测试结果_202609281710.md》。

## 结论

把 Reloc3r 管线中的 NetVLAD(Pitts30K) top-10 检索换成 MegaLoc(gberton，8448 维) top-10——其余环节（Reloc3r-512 relpose、运动平均、基线过滤、帧集、外参链、GT=/map）完全不变——**端到端精度有实质提升，提升全部来自检索排序质量；推理耗时几乎不变**：

| 查询包 | 检索器 | top-10 全进平均 med/p90 (m) | base-max 3 med/p90 (m) | bm3 terr<0.5/1m |
|---|---|---|---|---|
| 割草同天 062224 | NetVLAD | 0.58 / 4.34 | 0.254 / 1.64 | 68% / 83% |
| 割草同天 062224 | **MegaLoc** | 0.35 / 2.53（med **−39%**、p90 **−42%**） | 0.256 / **1.28**（p90 −21%） | 72% / **86%** |
| 割草跨天 081533 | NetVLAD | 0.46 / 4.16 | 0.256 / 2.06 | 73% / 84% |
| 割草跨天 081533 | **MegaLoc** | 0.33 / 2.10（med −28%、p90 **−50%**） | **0.228** / **1.46**（med −11%、p90 −29%） | **72% / 82%** |
| 大楼 0923 | NetVLAD | 0.15 / 1.32 | 0.122 / 0.74 | 85% / 93% |
| 大楼 0923 | **MegaLoc** | 0.13 / 0.93（med −13%、p90 −30%） | 0.122 / 0.72（持平） | 85% / 92% |

- 旋转不受影响（med 1.33 / 2.37 / 0.70°，与 NetVLAD 版一致）——旋转从来不是检索的锅。
- top-10 命中@2m：MegaLoc 100 / 99.6 / 100% vs NetVLAD 99.6 / 99.0 / 100%。"有没有对帧"两边都几乎不出错；差异在**排序**——MegaLoc 把近基线对帧排得更靠前，喂给 relpose 的候选几何条件更好、远基线污染更少 → top-10 口径尾部砍半（p90 4.3→2.5 m），base-max 3 口径继续受益（割草 p90 1.64→1.28、2.06→1.46 m）。
- **提升多少（一句话）**：不改动平均口径时，med 提升 28–39%、p90 提升 30–50%；配 base-max 3 时 med 提升 0–11%、p90 再降 21–29%。割草场景（尤其跨天）是主要受益者；大楼批几何本来就宽松，换检索器只微调。
- 与前批结论一致：换检索器改变的是尾部与候选质量，不改变 Reloc3r 沿行进方向无尺度这一机制性弱点。

误差分解（bm3 口径，med/p90，沿行进 / 水平横向 / 竖直，m；`data/zc_megaloc_reloc3r/decomp.json`）：

| 查询 | 分量 | NetVLAD bm3 | MegaLoc bm3 |
|---|---|---|---|
| 同天 | 沿行进 | 0.144 / 1.77 | 0.150 / **1.33** |
| 同天 | 横向 / 竖直 | 0.089 / 0.046（p90 0.30 / 0.15） | 0.077 / 0.044（p90 0.25 / 0.14） |
| 跨天 | 沿行进 | 0.188 / 2.48 | 0.175 / **1.58** |
| 跨天 | 横向 / 竖直 | 0.126 / 0.046（p90 0.39 / 0.11） | 0.109 / 0.041（p90 0.36 / 0.11） |
| 大楼 | 沿行进 / 横向 / 竖直 | 0.097 / 0.040 / 0.036（p90 0.85 / 0.11 / 0.10） | 0.096 / 0.040 / 0.034（p90 0.82 / 0.11 / 0.11） |

改善集中在沿行进分量尾部（p90 −25~−36%），横向/竖直小幅受益；有符号滞后均 ≈0（−0.06~+0.02 m）。

## 耗时与资源变化

在线段主体（relpose + 运动平均）不动，替换检索器只影响检索段：

| 项 | NetVLAD 管线 | MegaLoc 管线 | 变化 |
|---|---|---|---|
| 描述子提取（GPU 实测） | ≈13 ms/帧（batch 口径，含 IO） | batch64：**5.3 ms/帧**；单帧：37.2 ms | 批处理 ~2.5× 快；单帧延迟同量级（37 vs 35 ms） |
| top-10 检索计算 | 全对全余弦（db≤894，<1 ms/帧） | 同 | 无变化 |
| relpose 推理 | 0.334–0.337 s/帧（top-10） | 0.334 s/帧（同一模型不动） | **无变化** |
| 运动平均 | 0.32 ms/帧（CPU） | 同 | 无变化 |
| 检索段 GPU util / 功率 | 46.7% / 77 W（retrieve 35.4 s 全程含建库） | 6.1% / 17.5 W（200 帧 bench 段） | MegaLoc 前向更快、瞬时负载更低 |
| 检索段显存 | 1522 MiB 峰值 | 2216 MiB 分配（峰值 3254 MiB，322² 输入权重更大） | **+~0.7–1.7 GiB** |
| 端到端 eval 段（3 包全量 relpose+平均） | 77.0% util mean / 100% p95，3748 MiB，82 W | 72.5% / 100%，3754 MiB，79.5 W | 基本不变（relpose 主导） |

一句话：**换 MegaLoc 不增加在线时间预算**（relpose 33 ms/对不变，检索段批处理反而更快、单帧持平），代价是显存多 ~1 GiB 级；换来割草场景 p90 −20~50%、跨天 med −11%。

## 口径与局限

1. top-10 直接复用 MegaLoc 评测已存的 `order`（帧集、GT 链与 Reloc3r 评测完全相同，排序可无损替换），检索段零重复推理；两文档数字严格可比。
2. GT=/map 在线融合定位，对 RTK 刚体拟合残差 p50≈0.39 m：bm3 口径 med 0.23–0.26 m 已在噪声底内，绝对精度主张按基线文档口径打折（比较检索器的相对差值不受此影响）。
3. `perf_*.json` 的 `host_mem_used_mean_gib` 字段实测单位为 MiB（本批 eval 19363 MiB≈19 GiB），字段名笔误，不影响对比。
