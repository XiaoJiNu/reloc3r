# Reloc3r 在 ZC 自采数据集上的重定位测试方案

日期：2026-09-28 11:10（方案评审稿，未执行测试）
环境：conda env `mv2d`（/data/software/conda/anaconda3/envs/mv2d，torch 2.7.1+cu128，RTX 5090）

## 0. 一句话路线

把三个 mcap 包整理成"7Scenes 风格"的图片+位姿目录，复用仓库现成的检索(NetVLAD top-10)→ Reloc3r-512 相对位姿回归 → 运动平均求绝对位姿这条 `eval_visloc.py` 主链路，写一个独立入口脚本 `eval_zc.py`，用 `/map` 话题位姿同时充当 db 位姿与查询 GT，输出平移/旋转误差（跨天与同天分开统计）。

## 2. 关键设计决策（请重点评审）

1. **GT 来源 = `/map` 话题**。它是 ZC 在线系统的融合定位输出（RTK 锚定，此前审计 RTK 状态固定占比 100%），不是独立真值。因此本测试度量的严格说是"Reloc3r 相对在线系统定位结果的一致性"，这是当前数据条件下唯一三包同系、逐帧稠密的位姿源，先按此口径出数。若需要独立真值（RTK→ENU+杆臂反解）可作后续追加。
2. **相机位姿 = /map 位姿经雷达系外参换算**（用户裁定：一切以 lidar 系为枢纽，不引入车体系）。实测几何（064638 包，579 个运动帧）：
   - /map 体 x 轴与行进方向夹角 p50=3.1° → 体 x = 雷达 x（前进）；
   - 体 z 轴与 map 竖直轴点积≈0.02 → 体系是 x前/y竖直/z横向，= 雷达系(x前,y左,z下)绕 x 轴 ±90°；
   - camera_01 光轴(=-y_lidar 偏下 10.4°)与行进方向 p50=87° → **camera_01 是侧向相机**（画面中出现"坐在雷达旁、雷达系 az≈-97°"的人员，与标定 `image_02/lidar_to_image_02.txt` 的光轴方向互证）。
   - 因此 `T_map_cam = T_map_body · Rx(±90°) · inv(T_lidar_cam)`。Rx 的 ± 号（体系 y 向上/向下）数据无法先验区分，用 40 帧 sanity 跑自动定符号，随后全程一致使用并在结果文档记录。
   - 标定目录内所有外参以雷达系为枢纽（lidar→image_02、lidar→4鱼眼、IMU→lidar=I）；无 lidar→车体外参，本方案也不需要。`calib_velo_to_cam.txt`（180° 滚转错误）弃用。
3. **抽帧密度**：db（建图包 064638）每 5 帧取 1 ≈ 2 Hz ≈ 690 张；查询每包同样每 5 帧取 1 ≈ 750+700 张。topk=10、Reloc3r-512、`--amp 1`。预估 relpose 推理 1450×10≈1.45 万次，5090 上 20–30 分钟，可接受；更密只会拉长耗时，精度口径不变。
4. **不改动仓库现有代码**：新增独立脚本 `eval_zc.py`（约 150 行），三段式：
   - `extract`：mcap → `data/zc/<scene>/frame-XXXXXX.color.png` + 同步的 4×4 c2w `frame-XXXXXX.pose.txt`（时间戳最近邻同步 /map↔image，同步残差一并统计）；
   - 检索：复用 `reloc3r/image_retrieval/topk_retrieval.py` 的 `TopkRetrieval` + NetVLAD（Pitts30K 权重，上次 7Scenes 已下过）；
   - 回归+平均+评分：复用 `setup_reloc3r_relpose_model` / `inference_relpose` / `Reloc3rVisloc.motion_averaging` / `reloc3r/utils/metric.py`。dataset 适配类 `ZcRetrieval`/`ZcRelpose` 照抄 `sevenscenes_retrieval.py`/`sevenscenes.py` 的接口，仅改路径寻址与内参（fx=366.1 等）。

## 3. 执行步骤（评审通过后）

1. 导出图片与位姿（两查询包 + 建图包），产出统计：帧数、同步残差 p50/p95、三包轨迹覆盖图（PNG 俯视轨迹叠画，可浏览）。
2. 建 db 描述子 + 检索 top-10，落盘 pair 文件（可复用）。
3. Reloc3r-512 逐对推理 → 运动平均 → 逐查询帧误差。
4. 汇总指标（每查询包单列 + 合计）：
   - 平移误差中位数 / p90（米）
   - 旋转误差中位数 / p90（度）
   - 成功率：terr<0.25/0.5/1 m 且 rerr<5°/10°/20° 的帧占比（7Scenes 口径外，补户外尺度常用阈值）
   - 跨天（20260920 查询）与同天（20260921_062224 查询）分开报告
5. 可视化抽查：随机 8 个查询帧的"检索到的 top-1 db 图 + 预测位姿 vs GT 位姿"叠框/点云对照 PNG，保证结果可肉眼核查。
6. 结果写入 `docs/zc数据集上测试/zc数据集上测试reloc3r效果_YYYYMMDDHHMM.md`（结尾带时间戳），记录环境、命令、口径与全部数字。

## 4. 风险与对策

| 风险 | 对策 |
|---|---|
| /map 与图像时间戳不同步造成 GT 抖动 | 同步残差>100 ms 的帧剔除并计数 |
| 检索错误导致离群绝对位姿 | 报告里同时给运动平均前的逐对候选误差分布，区分"检索失败"与"回归失败" |
| 查询与建图轨迹不重叠的帧无意义 | 只评 GT 距 db 轨迹包络 ≤ 一定范围（如 15 m）的帧，剔除占比写入文档 |
| NetVLAD 对低矮割草视角域差 | 检索命中率（top-10 中包含 GT 距离<2 m 的 db 帧的比例）单独报告 |

## 5. 不做的事（YAGNI 声明）

- 不做鱼眼/多相机、不用 LiDAR 点云、不做尺度学习或 PnP 混合；
- 不训练/微调 Reloc3r（本次是零样本泛化测试）；
- 不改 `eval_visloc.py`/`wild_visloc.py` 本体。
