## 0. 一句话路线

三个 mcap 包整理成 7Scenes 风格的「图片 + 4×4 c2w 位姿」目录（建图包 20260921_064638 = db，其余两个 = query），完全复用仓库现成链路：NetVLAD 检索 top-10 → Reloc3r-512 逐对相对位姿回归 → 运动平均出绝对位姿 → 与 `/map` 位姿（经标定外参换算到相机系）比对得平移/旋转误差。新增独立入口 `eval_zc.py` + 两个 dataset 适配类，不改仓库现有代码。

### 1.1 轨迹核验（关键，已画图确认）

三包 `/map` 轨迹为**同一个闭合环形路径**（近似四边形，x∈[-25.7,32.7]、y∈[-24.6,15.7]，周长约 327 m，包围约 1300 m² 草坪），三包**同向**（均从 (-19.3,15.4) 起顺时针绕行），叠画仅角点处有分米级差异。叠图存档：`docs/zc数据集上测试/tools/traj_all.png`（评审时可直接查看）。查询帧与 db 轨迹天然全程重叠，§4 的「不重叠剔除」预计剔除量为 0。

### 1.2 相机外参链（v2 修正重点）

`T_lidar_cam` 取标定目录 `image_02/lidar_to_image_02.txt`（README §1 明确采用、人工验证过；弃用含 180° 滚转的 `calib_velo_to_cam.txt`）。实测该外参：俯仰 **-79.96°**（z-down 雷达系→z-forward 光学系的标准换轴量）、光心位于雷达系 (0.01, -1.42, 1.01) m、前方 ~1.75 m 处——**必须参与链路，不能当单位阵**（11:10 版已指出，v2 保留）。

`/map` 朝向核验（本版新增实测）：yaw 与轨迹行进方向的差 ψ0 = 1.4°/2.4°/3.2°（三包），roll/pitch 中位数均在 ±1° 内（p95 < 3.5°，草坡起伏）→ `/map` 朝向就是车体前向、map 系近水平，无隐藏的 90° 换轴。相机 c2w 链取：

```
T_map_cam = T_map_lidar @ T_lidar_cam^-1 ， T_map_lidar = /map 位姿（平移+四元数）
```

剩余假设（唯一无法用数据闭合的环节，显式声明）：`/map` 的刚体参考 = hesai 雷达系。bag 无 tf 可证；但 z 范围 [-0.82, 0.09] 与「雷达在车上的安装高度」量级吻合、yaw-行进方向差仅 ~2-3°（雷达若横装该差应为 90°），假设成立概率极高。若测试结果出现系统性偏差，首个排查点即此假设（可用 RTK+杆臂反解交叉验证，见 §5）。

## 2. 关键设计决策（请评审）

1. **GT 与 db 位姿同源 = `/map`**。它是在线融合定位（RTK 全程 status=2 fixed，此前已实测 100%），不是独立真值。本次度量口径因此是「Reloc3r 相对在线系统的一致性」。没有独立米制真值可用（RTK→ENU 还差杆臂/天线原点两笔未标定量），先按此口径出数；如需独立真值走 §5 追加项。
2. **图像预处理 = 去畸变**（v2 新增）。用 bag 内 plumb_bob 系数做 `cv2.undistort`（alpha=0 保内参形状），640×480 → 640×480 针孔图，再去喂模型。一次性离线完成，与抽帧同遍历。
3. **抽帧**：db 每 5 帧取 1（≈2 Hz，~690 张，帧间距 ≈ 0.6 m——比指南建议的 2-5 m 密 3~8 倍，运动平均的平移尺度锚更稳）；查询每包同样每 5 帧取 1（各 ~700/750 张）。分辨率 (512,384)、topk=10、Reloc3r-512、amp=1——与 7Scenes/MegaDepth 复现口径完全一致，结果可与论文数字同轴比较。
4. **评测指标**（沿用 7Scenes 口径 + 补户外阈值）：
   - 中位/mean/p90 平移误差（m）、中位/mean/p90 旋转误差（°）
   - 成功率：terr<0.25/0.5/1 m（三档，各不限旋转）
   - 跨天（20260920）与同天（20260921_062224）**分开报告**
   - 诊断指标（防「整体数字看着还行、其实一半是检索失败」）：运动平均前逐对候选误差分布、检索命中率（top-10 内含 GT 距 <2 m db 帧的 query 占比）、运动平均平移 SVD 最小奇异值占比分布（直线退化监测——本数据是环形路径，预期能收敛，留数验证）
5. **代码落点**（不改动仓库现有文件）：
   - `eval_zc.py`（新，~200 行）：`extract` / `retrieve` / `eval` 三子命令，断点可续（中间产物落盘复用）
   - `reloc3r/datasets/zc_retrieval.py`（新，~60 行）：`ZcRetrieval` / `ZcRelpose`，照抄 sevenscenes 两件套接口，仅改寻址与内参
   - 数据目录：`data/zc/<bag名>/seq-01/frame-XXXXXX.color.png + .pose.txt`
   - 磁盘预算：三包共 ~3900 张 PNG（640×480 去畸变后）≈ 2.5 G，/data 现余 233 G，无压力

## 3. 执行步骤（评审通过后）

1. `extract`：三个包 → 图（去畸变）+ 位姿（相机 c2w）落盘；产出：帧数、同步残差表（§1 已有预期值）、三包轨迹叠画 PNG、db/query 抽帧覆盖图。
2. `retrieve`：NetVLAD(Pitts30K，已缓存) 建 db 描述子 + query top-10 检索，落盘 `_db-q_pair_info/zc_*.npy`。
3. `eval`：Reloc3r-512 逐对回归（~1.5 万对，curope + amp=1，按 22.8 it/s 估 ~11 min 纯推理）→ 运动平均 → 逐帧误差。
4. 汇总出数（§2.4 全部指标，分查询包列表）+ 可视化抽查：随机 8 个查询帧的「query 图 + top-1 检索 db 图 + 预测/GT 轨迹俯视叠画」PNG（可浏览，逐帧可人工核查）。
5. 结果文档 `docs/zc数据集上测试/zc数据集上测试reloc3r效果_YYYYMMDDHHMM.md`（结尾带时间戳），记录环境、命令、口径、全部数字与可视化文件路径。

## 4. 风险与对策（v2 收敛后）

| 风险 | 实测状态 | 对策 |
|---|---|---|
| /map↔图像时间戳不同步 | 已排除：p95≈11 ms | 不需处理，残差表照记 |
| 检索失败污染绝对位姿 | 未测（域差：低视角+草地重复纹理是 NetVLAD 弱项） | 逐对候选误差分布 + 检索命中率单独报告；必要时 topk 提到 20 复跑一轮（成本 ~20 min） |
| 直线运动退化（运动平均病态） | 已排除大半：环形路径，视线几何好 | SVD 最小奇异值占比分布留档 |
| query-db 无重叠 | 已排除：三包同轨迹 | 剔除逻辑保留，预期剔除 0 |
| /map 刚体系假设错误 | 无法从 bag 证实 | §1.2 显式声明；结果出系统性偏差时优先排查，备选 RTK 反解交叉验证 |
| 单帧噪声大（户外宽基线 AUC@5 论文仅 ~50） | 已知特性 | 本次测的就是「逐帧独立重定位」口径，不做时序滤波（YAGNI，见 §6） |

## 5. 不做的事（YAGNI）

- 不做鱼眼/多相机、不用 LiDAR/RTK 独立真值链（除非主结果出现系统性偏差触发 §1.2 排查）
- 不训练/微调、不做时序滤波/EKF 融合（本次回答的问题是「逐帧重定位裸精度」）
- 不改 `eval_visloc.py`/`wild_visloc.py` 本体

## 6. 评审确认点

1. GT 口径用 `/map`（在线系统一致性）可否接受？还是要先走 RTK 独立真值（多半天工作量，标定缺失项需采集队补）？
2. db 抽帧每 5 帧（~690 张）密度可否？更密（每 2 帧 ~1700 张）检索/回归耗时翻 ~2.5 倍，精度收益边际。
3. 除 topk=10 主结果外，是否需要 topk=20 的对照行？（先跑 10，20 视检索命中率再定——默认不做）
